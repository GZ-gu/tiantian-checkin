# 打卡了吗 MVP PRD

> 历史版本：本文件记录 2026-07-09 前后的早期探索，包含照片打卡、成长等级、自定义目标天数等已退出 V1.1 的方案。现役规则请只查看 [天天打卡_V1.1_PRD.md](./天天打卡_V1.1_PRD.md)。

## 1. 产品定位

“打卡了吗”是一款面向中小学生和家长的轻量学习打卡小程序。它帮助家长发布自定义学习任务，让孩子每天完成线下任务后上传打卡证明，并通过勋章、等级、分享卡片和家长奖励建议，增强孩子的坚持动力。

一句话定位：

把“每天学习一下”变成孩子看得见、攒得住、晒得出去的小成就。

## 2. 目标用户

### 家长

家长是任务创建者、监督者和奖励兑现者。家长希望孩子坚持背单词、阅读、练字、口算、运动、乐器等长期积累型任务，但不想每天只靠催促。

### 中小学生

孩子是任务执行者。孩子需要即时反馈、可视化进度、勋章奖励和群分享带来的成就感，从“被要求完成”变成“我想把这枚勋章点亮”。

## 3. 核心问题

当前微信群打卡方式可以用，但体验粗糙：

- 群接龙和文字打卡缺少爽感。
- 孩子只是在完成家长要求，缺少可感知奖励。
- 家长翻群消息统计麻烦。
- 长期坚持的进度不直观。
- 打卡结果不适合展示和传播。

## 4. MVP 核心目标

第一版只验证一个闭环：

家长创建任务，孩子每日打卡，勋章逐步点亮，生成分享卡发到微信群，群内反馈和家长奖励推动孩子继续坚持。

## 5. 核心流程

1. 家长新建任务。
2. 家长设置任务名称、周期、目标天数、打卡方式、奖励建议。
3. 孩子每天完成线下任务。
4. 孩子上传照片、文字或勾选完成进行打卡。
5. 系统记录连续天数和成长值。
6. 灰色勋章按进度逐步填充为彩色。
7. 达成目标后点亮勋章。
8. 系统生成分享卡片。
9. 家长或孩子分享至微信群。
10. 家长按约定给予实物奖励或权益奖励。

| 模块 | 功能 | 描述 | 优先级 |

| 任务发布 | 设置奖励建议 | 家长可填写达成勋章后的奖励，如零花钱、游戏时间、亲子活动 | P0 |

## 7. 任务配置项

家长发布任务时，第一版建议包含：

- 任务名称
- 任务类型：背单词、阅读、练字、口算、运动、乐器、自定义
- 目标天数：3 / 7 / 14 / 21 / 30 / 自定义
- 打卡频率：每天 / 每周几天
- 打卡方式：拍照 / 文字 / 勾选
- 勋章名称
- 奖励建议
- 是否生成分享卡

## 8. 勋章与奖励机制

### 勋章进度

勋章默认是灰色。每完成一次打卡，勋章填充一部分彩色。

例如 7 天阅读勋章：

- 第 1 天：填充 1/7
- 第 4 天：填充 4/7
- 第 7 天：整枚勋章点亮

### 家长奖励建议

系统只提供“奖励建议”，由家长自行决定是否兑现。

示例：

- 连续 3 天：一次夸奖或小贴纸
- 连续 7 天：10 元零花钱或周末多玩 30 分钟
- 连续 21 天：选一本书或一次亲子活动
- 连续 30 天：一次更大的家庭奖励

产品文案要避免“用钱控制孩子”，重点表达“努力值得被看见，也值得被认真回应”。

## 9. 成长等级机制

第一版可以加入轻量等级，但不要做复杂游戏系统。

规则：

- 每完成 1 次打卡，成长值 +1
- 成长值累计到一定数量后升级
- 等级只用于展示，不解锁复杂功能

示例：

- Lv.1 刚开始：0-2 点
- Lv.2 小小坚持者：3-6 点
- Lv.3 连续行动者：7-20 点
- Lv.4 勋章收集者：21-49 点
- Lv.5 长期主义者：50 点以上

## 10. 页面结构

第一版建议 5 个页面：

1. 首页
   - 今日任务
   - 当前勋章进度
   - 连续打卡天数
   - 快速打卡入口

2. 打卡页
   - 任务说明
   - 上传照片 / 填写文字 / 勾选完成
   - 打卡成功反馈

3. 勋章页
   - 已获得勋章
   - 进行中的灰色勋章
   - 勋章填充进度

4. 分享卡页
   - 今日分享卡预览
   - 保存图片
   - 分享到微信

5. 家长任务管理页
   - 新建任务
   - 编辑任务
   - 查看孩子打卡进度
   - 设置奖励建议

## 11. 分享卡内容

分享卡片第一版建议包含：

- 孩子昵称
- 今日任务名称
- 今日完成状态
- 连续打卡天数
- 当前勋章进度
- 已点亮勋章
- 本周完成情况
- 一句短文案

示例文案：

- 今天也完成啦
- 阅读勋章进度 5/7
- 连续坚持 7 天
- 我的英语小勋章点亮了

## 12. 第一版不做什么

第一版明确不做：

- AI 批改
- 英语发音评分
- 自动识别作业质量
- 群排行榜
- 班级管理
- 老师端
- 课程售卖
- 复杂社交关系
- 自动发微信群
- 付费系统

第一版先验证孩子是否愿意为了点亮勋章持续打卡，以及家长是否愿意把分享卡发到群里。

## 13. 验收标准

第一版完成后，应满足：

- 家长能创建自定义任务。
- 孩子能完成一次打卡。
- 打卡后能看到勋章填充变化。
- 达成目标后能点亮勋章。
- 能生成适合发微信群的分享卡片。
- 家长能查看任务进度。
- 奖励建议能被记录和提醒。

## 14. 产品风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 变成普通打卡工具 | 如果只做提交和统计，差异不足 | 强化勋章填充、分享卡、奖励兑现 |
| 孩子作弊 | 上传照片不代表真的学习 | 第一版只验证坚持行为，不验证学习效果 |
| 过度攀比 | 群内对比可能造成压力 | 第一版不做公开排行榜，只展示个人成就 |
| 家长配置太复杂 | 字段太多会影响发布任务 | 默认模板 + 自定义补充 |
| 奖励导向过强 | 孩子可能只为奖励学习 | 文案强调坚持和成长，奖励只是家庭回应 |

## 15. 给线框图的一句话

线框图优先画清楚这个闭环：

家长发布任务 → 孩子今日打卡 → 勋章注水填色 → 生成分享卡 → 家长查看进度与兑现奖励。
